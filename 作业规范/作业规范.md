# 作业规范

## 1. 需求文档规范

### 1.1 文档结构
- 需求文档必须严格按照《需求文档模板》的结构撰写
- 变更记录必须放在文档的第一部分，便于查看
- 每个功能模块必须包含字段定义、操作逻辑、状态流转和数据权限

### 1.2 文档内容
- 文档内容必须完整，包括功能需求、非功能需求、用户故事等
- 字段定义必须包含字段名称、字段类型和字段取值逻辑
- 操作逻辑必须包含操作按钮、操作逻辑、成功提示和错误提示
- 状态流转必须清晰描述状态之间的转换关系
- 数据权限必须明确不同角色的权限限制

### 1.3 文档格式
- 文档必须使用Markdown格式
- 表格必须使用Markdown表格语法
- 代码块必须使用Markdown代码块语法
- 文档中不能存在乱码
- 文档必须使用UTF-8编码

## 2. 原型规范

### 2.1 原型结构
- 原型必须使用统一的导航栏结构
- 导航栏必须包含所有功能模块的链接
- 页面布局必须符合设计风格要求

### 2.2 交互逻辑
- 原型中的按钮交互必须100%还原需求文档中的描述
- 所有操作按钮必须实现相应的功能
- 操作成功或失败时必须显示相应的提示信息
- 模态框必须正确实现打开和关闭功能
- 表单提交必须包含必要的验证

### 2.3 响应式设计
- 原型必须支持响应式设计
- 在不同屏幕尺寸下必须保持良好的显示效果

## 3. 作业流程规范

### 3.1 文档更新流程
1. 根据需求变更更新需求文档
2. 确保文档结构符合模板要求
3. 检查文档中是否存在乱码
4. 保存更新后的文档

### 3.2 原型更新流程
1. 根据需求文档更新原型
2. 确保所有按钮交互与需求文档一致
3. 测试原型的各项功能
4. 保存更新后的原型

### 3.3 版本控制流程
1. 每次更新后必须将文件保存到本地
2. 每次更新后必须将文件更新到GitHub
3. 提交代码时必须填写清晰的提交信息
4. 定期进行代码备份

## 5. 常见问题及解决方案

### 5.1 文档乱码问题
- **问题**：文档中出现乱码
- **解决方案**：使用UTF-8编码保存文档，确保编辑器设置正确

### 5.2 原型交互不一致问题
- **问题**：原型中的按钮交互与需求文档不一致
- **解决方案**：严格按照需求文档中的操作逻辑实现原型

### 5.3 文档结构不符合要求问题
- **问题**：文档结构与模板不一致
- **解决方案**：使用模板创建文档，确保结构符合要求

### 5.4 版本控制问题
- **问题**：文件未及时更新到GitHub
- **解决方案**：建立定期更新机制，确保代码及时提交

## 6. 其他规范

### 6.1 命名规范
- 文件名称必须使用中文或英文，避免使用特殊字符
- 文件夹结构必须清晰，便于管理

### 6.2 代码规范
- HTML代码必须使用语义化标签
- CSS代码必须使用清晰的命名约定
- JavaScript代码必须使用规范的命名和缩进

### 6.3 文档规范
- 文档语言必须清晰、准确
- 避免使用模糊、歧义的描述
- 确保文档内容与实际需求一致

### 6.4 沟通规范
- 定期与团队成员沟通项目进展
- 及时反馈问题和解决方案
- 保持良好的沟通记录
