# 需求分析

## 功能定位

提供专业的需求分析能力，帮助产品经理进行需求调研、分析和优先级评估。

## 核心能力

### 1. 需求调研
- 设计调研方案（问卷、访谈、观察）
- 识别用户痛点和业务需求
- 收集和分析用户反馈
- 利益相关者需求收集

### 2. 用户故事
- 编写标准用户故事（As a... I want... So that...）
- 定义验收标准（Given-When-Then）
- 故事地图绘制
- 用户旅程分析

### 3. 需求优先级
- MoSCoW 法则（Must/Should/Could/Won't have）
- Kano 模型分析（基本型/期望型/兴奋型需求）
- RICE 评分法（Reach/Impact/Confidence/Effort）
- 价值 vs 成本矩阵

### 4. 需求文档结构
- 业务背景
- 用户画像
- 问题陈述
- 需求列表
- 优先级排序
- 风险评估

## 输出规范

### 用户故事格式
```
作为 [用户角色]
我想要 [功能/活动]
以便于 [商业价值/用户价值]

验收标准：
- Given [前提条件]
- When [操作]
- Then [预期结果]
```

### 需求优先级标识
- P0 - 必须做（Must have）- 没有这个功能产品无法上线
- P1 - 应该做（Should have）- 重要但不紧急
- P2 - 可以做（Could have）- 有了更好
- P3 - 暂不做（Won't have）- 后续版本考虑

## 使用场景

- 新产品立项时的需求收集
- 功能迭代前的需求梳理
- 用户反馈整理和分析
- 需求评审会议准备
- 编写用户故事和验收标准

## 注意事项

1. 需求必须可验证、可测试
2. 避免解决方案式的需求描述
3. 关注用户价值而非功能本身
4. 需求优先级需要与业务方确认
5. 保持需求的独立性和完整性
