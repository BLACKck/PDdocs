## 2. 项目概述

### 2.1 项目背景
为小鹏汽车总部销售管理中台人员和门店人员设计客户管理后台，包含客户线索管理、客户商机管理、客户订单管理、待售车辆管理、销售政策管理、门店线索及订单查看、门店管理（包含入驻与退出机制）、订单配车、门店信息管理等功能。

### 2.2 项目目标
- 建立统一的客户管理平台，提升销售管理效率
- 实现从线索到订单的全流程管理
- 优化门店管理和配车流程
- 提供数据支持和分析能力

### 2.3 术语定义
| 术语 | 解释 |
|------|------|
| 线索 | 潜在客户信息，尚未转化为商机 |
| 商机 | 有购买意向的潜在客户，已进入销售流程 |
| 订单 | 客户已确认购买的车辆订单 |
| 配车 | 为订单分配具体车辆的过程 |
| 门店 | 小鹏汽车的销售服务网点 |

## 3. 功能需求

### 3.1 客户线索管理

#### 3.1.1 字段定义
| 字段名称 | 字段类型 | 字段取值逻辑 | 验证规则 |
|----------|----------|--------------|----------|
| 线索ID | 字符串 | 系统自动生成 | 唯一 |
| 客户姓名 | 字符串 | 必填 | 长度1-50字符 |
| 手机号码 | 字符串 | 必填，11位数字 | 11位数字，格式验证 |
| 意向车型 | 字符串 | 下拉选择 | 必选 |
| 来源渠道 | 字符串 | 下拉选择（线上、线下、推荐等） | 必选 |
| 状态 | 字符串 | 待跟进、跟进中、已转化、已放弃 | 系统自动更新 |
| 创建时间 | 日期时间 | 系统自动生成 | 系统自动填充 |
| 跟进人 | 字符串 | 关联用户表 | 必选 |
| 跟进记录 | 文本 | 多行文本 | 长度0-1000字符 |

#### 3.1.2 筛选字段
- 线索状态
- 来源渠道
- 意向车型
- 创建时间范围
- 跟进人

#### 3.1.3 操作逻辑
- 新增线索：填写客户信息，选择意向车型和来源渠道
- 编辑线索：修改线索信息
- 删除线索：删除无效线索
- 跟进线索：记录跟进内容，更新线索状态
- 转化线索：将线索转化为商机

#### 3.1.4 状态流转
待跟进 → 跟进中 → 已转化/已放弃

#### 3.1.5 数据权限
- 总部：查看所有线索，可分配线索给任意门店
- 门店：查看分配给本门店的线索，只能管理本门店的线索
- 销售人员：查看分配给自己的线索，只能管理分配给自己的线索

#### 3.2.5 数据权限

## 4. 非功能需求

### 4.1 性能需求
- 系统响应时间：页面加载时间不超过3秒
- 并发处理能力：支持1000人同时在线
- 数据处理速度：批量操作响应时间不超过5秒

### 4.2 安全需求
- 数据加密：敏感数据加密存储
- 访问控制：基于角色的权限控制
- 日志记录：所有操作都有详细日志
- 定期备份：数据定期备份

### 4.3 可用性需求
- 系统可用性：99.9%
- 故障恢复：系统故障后30分钟内恢复
- 容灾备份：具备容灾备份机制

### 4.4 易用性需求
- 界面友好：操作界面简洁明了
- 操作便捷：常用功能一键可达
- 响应式设计：支持不同设备访问
- 帮助文档：提供详细的使用帮助
