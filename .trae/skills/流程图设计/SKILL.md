# 流程图设计

## 功能定位

提供专业的流程图绘制能力，帮助产品经理清晰表达业务流程、用户旅程和系统状态。

## 流程图类型

### 1. 业务流程图
- 跨部门协作流程
- 业务处理流程
- 审批流程
- 订单流程
- 支付流程

### 2. 用户旅程图
- 用户体验流程
- 任务完成路径
- 触点分析
- 情绪曲线

### 3. 状态流程图
- 订单状态流转
- 用户状态变化
- 审核状态流转
- 生命周期管理

### 4. 数据流程图
- 数据流向
- 数据处理
- 数据存储
- 数据交互

### 5. 系统架构图
- 系统模块划分
- 模块间关系
- 技术架构
- 部署架构

## 标准符号规范

### 业务流程图符号
- ○ 椭圆 - 开始/结束
- □ 矩形 - 处理步骤
- ◇ 菱形 - 判断/决策
- → 箭头 - 流程方向
- ▱ 平行四边形 - 输入/输出

### 状态图符号
- ○ 圆形 - 状态
- → 箭头 - 状态转换
- 箭头标注 - 转换条件

## 绘制规范

### 布局规范
- 从上到下、从左到右
- 避免交叉线
- 保持对称和平衡
- 合理分组和分层

### 标注规范
- 步骤描述简洁明了
- 判断条件清晰完整
- 异常流程也要标注
- 使用统一术语

### 颜色规范
- 正常流程 - 绿色/蓝色
- 异常流程 - 红色/橙色
- 判断节点 - 黄色
- 开始结束 - 深色

## 输出要求

### 完整性
- 覆盖所有业务场景
- 包含正常和异常流程
- 明确起点和终点
- 无死循环和断头路

### 可读性
- 层次清晰
- 逻辑连贯
- 便于理解
- 易于沟通

### 可执行性
- 可转化为代码逻辑
- 可指导开发实现
- 可用于测试用例设计

## 常用工具

- ProcessOn
- draw.io
- Visio
- Lucidchart
- 墨刀
- Axure

## 使用场景

- 需求分析和梳理
- 业务流程说明
- 开发沟通
- 测试用例设计
- 用户培训材料
- 流程优化改进

## 注意事项

1. 流程图要经过业务方确认
2. 复杂流程要分层绘制
3. 保持流程图与文档一致
4. 定期更新维护流程图
5. 注意流程的可实现性
